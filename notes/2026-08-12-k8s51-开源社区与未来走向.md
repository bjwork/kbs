K8s 的成功一半在技术，一半在社区治理。CNCF 表面托管 K8s，实质只做 Marketing，不干涉技术——这是 Google 刻意为之：用基金会中立性规避「Google 作风」争议，同时把技术主导权牢牢留在 K8s 社区自己手里。CNCF 如今是云计算领域的 Apache，但张磊点破一层：基金会从来不是开源项目成功的必要条件，本末倒置最危险。

K8s 社区治理的核心是 OWNERS + SIG 机制。每个目录放 OWNERS 文件声明 approver/reviewer，PR 必须 `/lgtm` + `/approve` 才合并，全程机器人自动化；功能开发走 Issue → SIG 讨论 → Design Proposal → KEP → 代码的硬流程。最关键的一条经验：把「搞政治」和「搞技术」的人分开——OpenStack 衰落就是反例，民主化治理没分主线旁线，低价值项目涌入拖垮核心演进。

我的判断：这套 OWNERS + SIG 机制比单一 Maintainer 模式健康得多，权力分散到目录粒度，新人有明确上升路径，也避免了「核心维护者倦怠」的死局。对想参与开源的工程师，张磊给的路径很实在——先在 SIG 周会冒泡、Issue 里刷存在感、再提小 PR，而不是一上来甩大重构。我自己在用 Claude Code 做知识管理时也借鉴了「机械归脚本、语义归人」的分工思路，本质和 K8s「CI 归机器人、判断归人」一脉相承。
