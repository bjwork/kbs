丁奇第 27 讲。一主多从切换的痛点：从库要找到「新主库上对应的同步位点」（binlog file + pos），但不同主库的 binlog 文件和位点不通用，传统做法要靠日志偏移量估算，复杂易错。**GTID（全局事务 ID）**：每个事务有全局唯一 ID（server_uuid:transaction_id），从库只需说「我执行到 GTID X 了」，新主库自动从 X+1 开始补。切换从「算位点」变成「报 ID」，一主多从切换可用性质变。

**对我的价值**：GTID 的价值不只是切换方便，是**把复制的对账单位从「物理位置」升格为「逻辑事务」**。物理位置依赖具体文件，跨实例毫无意义；逻辑 ID 全局通用。这个抽象升级跟分布式系统里 Lamport Clock / Vector Clock 解决「跨节点时序」是同一个思想。5.6+ 必开，没有不开的理由。

**立场**：作者建议「支持 GTID 就尽量用」，我完全同意且更进一步——**GTID 应该作为新库的默认开启项，写进部署模板**。不开 GTID 的主从架构在 2026 年就是技术债，切换时你一定会后悔。唯一注意点是 GTID 有限制（比如不能在事务里同时更新事务表和非事务表），但这些限制本身就是好的工程约束。
