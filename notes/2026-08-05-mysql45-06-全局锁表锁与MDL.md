丁奇第 6 讲。三种锁：全局锁 FTWRL（整库只读，主要用于逻辑备份——但官方 mysqldump 用 --single-transaction 拿一致性视图，才是 InnoDB 的正道）；表级锁（lock tables，引擎不支持行锁时代的遗物，代码里见到要追查）；**MDL 元数据锁**（5.5 引入，读写互斥，DDL 会堵在等 MDL 上，而 MDL 队列一旦堵住，后续所有对该表的访问全部排队——线上加个字段把库打挂的经典路径）。

**对我的价值**：MDL 的死锁链条值得背：session A 长事务持有 MDL 读锁 → session B DDL 等 MDL 写锁 → session C 后续所有查询排队在 B 后面 → 连接池打满 → 应用雪崩。解法：DDL 前查 information_schema.innodb_trx 有没有长事务；alter table 设 wait 超时（MariaDB/AliSQL 有 NOWAIT/SKIP LOCKED）。**小表 DDL 一样致命**——堵住的不是表大小，是 MDL 队列。

**立场**：这篇直接改变了我对「数据库变更窗口」的理解。以前觉得加字段是低风险操作，随便找个低峰期就做了；看完才知道风险不在操作本身，在于**有没有长事务在飞**。现在我的 DDL SOP 第一条：先查长事务，再上 DDL，缺一不可。
