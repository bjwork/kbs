丁奇第 34 讲。两种 join 算法：**Index Nested-Loop Join（NLJ）**——驱动表每行用被驱动表的索引精确查，比较次数≈驱动表行数，快；**Block Nested-Loop Join（BNL）**——被驱动表没索引可用，驱动表结果放 join_buffer，被驱动表全表扫逐行比对，比较次数 = 两表行数乘积，内存不够还要分段，慢且伤 CPU。结论：**被驱动表关联字段有索引，join 可用；没索引，别用**。驱动表选小的（过滤后行数少的）。

**对我的价值**：「DBA 不让用 join」的正确翻译是「不让用没有索引支撑的 join」。NLJ 本身没问题，问题出在很多 join 是临时写的，被驱动表关联字段没索引，一个查询扫全表乘积次。我的 SQL review 规则：**join 必须 explain，Extra 里不能出现 Using join buffer (Block Nested Loop)**，出现就驳回。

**立场**：join 在国内互联网被污名化了，根源是早期 MySQL 优化器弱 + 大表拆分流行。但现在的现实是：分库分表后**应用层 join**（查 N 次再内存拼）比数据库 join 更普遍也更难优化。我的立场：单机 MySQL 内，NLJ 能用就用，把复杂度留给数据库；跨库才不得不应用层拼。别为了「不用 join」的教条把简单问题复杂化。
