答疑篇常被跳过，其实最藏真问题——18 道思考题集中暴露了容器落地的高频痛点。挑几个我印象深的点评。

第一，控制器模式 vs 事件驱动（Q4）。这是理解 K8s 的灵魂题：控制器读的是「持续信号」（状态不变就一直 ADD），事件驱动只发一次。所以 K8s 不怕漏事件、不怕重启——重新 list 一遍状态就能对齐。这个设计直接决定了声明式系统的鲁棒性，比事件总线可靠得多。

第二，CRD 不是数据库（Q7）。API Object >1K、单对象 >1KB、高频请求就崩——这是踩过坑才懂。很多人拿 CRD 存业务数据当 KV 用，etcd 直接被拖垮。CRD 只适合配置管理，需要等待返回或校验返回值的场景上 API Aggregator。

第三，gVisor vs Kata（Q16）。gVisor 没有真 Guest Kernel，不能解决「宿主机 3.6 内核跑应用要 4.0」的问题，Kata 可以。但张磊断言用户态 Kernel 是安全容器未来——2026 年回看，gVisor 路线确实在演进，但 Kata（基于 VM）仍是需要强隔离场景（多租户、AI 推理沙箱）的主力，两者并未决出胜负。

我的判断：Taint Nodes by Condition（Q12）、Local PV 延迟绑定与 Dynamic Provisioning 冲突（Q8）、DaemonSet 早期自带调度（Q6）这几条，是生产排障时反复用到的硬知识，比正文更贴近实战。
