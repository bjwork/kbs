李运华「从 0 开始学架构」加餐。分布式环境下接口调用会失败、消息会丢失，只能靠重试，重试就要求幂等（同一操作多次执行结果不变）。「全局」是因为微服务拆分后同一请求不一定落到同一实例，要在全局多个微服务范围内保证幂等。

三种处理模式：
1. **事务级同步处理**：消息处理和业务处理同步，A 服务为 B 服务的事务分配全局 ID、写事件记录，B 服务幂等判断后同步执行。适合同步、简单、快的场景（如 TCC 扣库存）。
2. **事务级异步处理**：B 服务先存事件消息再异步处理业务，完成后更新状态。适合慢、长流程（如 SAGA）。
3. **接口级自动幂等**：接口提供方在处理逻辑里做幂等，防重复处理（如支付防重复扣款）。全局 ID 可由调用方生成（前端 Token）或从参数组装（用户 ID+订单 ID）。

四种幂等判断手段：数据库唯一索引（创建场景）、Redis SETNX（分布式事务/定时任务，推荐）、ZooKeeper 建节点（类似 Redis 但更重）、状态机（复杂状态用 `UPDATE ... WHERE status = X`）。
