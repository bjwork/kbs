结课测试本身只有 20 道选择题（12 单选 + 8 多选），原文只是入口没有题面。但测试题的价值不在答题，而在它是查漏补缺的索引——错哪道就回到对应笔记深读。

结合全专栏内容，我列几个最该自测的关键考点：①容器隔离的本质——Namespace 隔离视图 + Cgroups 限制资源，rootfs 只读 + Copy-on-Write，这三件套是白话容器基础的根；②Pod 设计模式——InitContainer、Sidecar 两大模式，WAR 包注入例子必须能复述；③控制器模型 vs 事件驱动——持续信号 vs 一次性事件，这是声明式鲁棒性的根源；④StatefulSet 的拓扑状态与存储状态——Pod 名稳定 + PVC 绑定，有状态应用为什么必须用 StatefulSet；⑤PV/PVC/StorageClass 三层抽象与 Local PV 延迟绑定；⑥CRI/CNI/CSI 三大接口的边界与职责；⑦声明式 API + CRD + Controller = Operator 的完整链路；⑧默认调度器的优先级与抢占、Taint/Toleration、Affinity；⑨HPA 基于 Custom Metrics 的工作链路（Prometheus → Adaptor → HPA）。

我的判断：这套题如果某道拿不准，说明对应模块还是「读过」而非「想通」——K8s 的考点之间是强耦合的，比如不懂 Cgroups 就读不懂资源模型，不懂资源模型就调不好调度器。我建议把错题对应的笔记用 Claude Code 重读一遍并追问「为什么这样设计」，比刷第二遍题有效。
