这篇是 kubeadm 的实战串联。几个关键节点值得记住：①Master 起来后 `kubectl get nodes` 是 `NotReady`，因为没装 CNI——`kubectl describe node` 会看到 `NetworkPluginNotReady`，CoreDNS 也 Pending，这是新手最常卡的第一道坎；②Weave/Flannel/Calico 都是 `kubectl apply -f` 一键装，CNI 是事实标准；③Worker 节点只需 `kubeadm join`，因为 Worker 和 Master 跑的都是 kubelet，区别只是 Master 多了几个系统 Pod；④Taint/Toleration 机制让 Master 默认不跑用户 Pod（`node-role.kubernetes.io/master:NoSchedule`），单机调试时 `kubectl taint nodes --all node-role.kubernetes.io/master-` 移除即可；⑤Rook 把 Ceph 容器化部署，体现了「云原生 = K8s 原生」——Operator + CRD 把复杂存储后端变成几条 apply。

**我的判断**：这章的真正价值不是步骤本身（步骤会随版本变），而是两个思想方法：**「我的工作能不能容器化？能不能借助 K8s API 和可扩展机制完成？」**——这两个问题到现在还是判断一件事该不该上 K8s 的试金石。踩坑方面，国内访问 gcr.io/quay.io 是老问题，换镜像源或代理是必修课；Dashboard 默认只允许 proxy 访问是安全设计，公有云上暴露 Dashboard 端口导致集群被挖矿的案例年年有。对于 AI 场景，Rook 这条路对训练任务的 checkpoint、模型权重持久化很有用，比手挂 NFS 可靠。
