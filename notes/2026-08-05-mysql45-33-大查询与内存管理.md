丁奇第 33 讲。不会打爆。Server 层**边算边发**：结果集不攒在 server 内存，算一批发一批（net_buffer 满就发）；客户端读得慢会堵住查询（show processlist 看到 Sending to client），但不耗内存。InnoDB 层，Buffer Pool 的 LRU 做了改进：新页先进 LRU 的 old 区，**停留超过 innodb_old_blocks_time（默认 1s）再被访问才晋升 young 区**——全表扫描的页只访问一次，永远不会污染 young 区，热数据安全。

**对我的价值**：「边算边发」解释了为什么 mysqldump 不会撑爆内存，也解释了为什么「客户端读一半不读了」会堵住数据库——不是 server 想攒着，是 TCP 缓冲区满了 server 写不动。Java 端用 JDBC 流式读（useCursorFetch）或设 fetchSize 就是为了配合这个机制，不然客户端内存先爆。

**立场**：LRU 的 old/young 分区是个教科书级的「防缓存污染」设计，思路可以搬走：**任何缓存都可能被一次性遍历污染，解法是延迟晋升**——不是第一次访问就进主缓存，而是证明「被重复访问」才进。本地缓存、CDN、甚至 LLM 的 context 管理都能套这个思想。
