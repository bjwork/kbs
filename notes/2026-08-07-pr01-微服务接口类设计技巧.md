李运华「从 0 开始学架构」加餐。微服务拆分后「服务分布式」带来的挑战：前端一个页面要请求多个微服务接口，导致请求性能差（来回网络消耗）、带宽浪费（大量小请求的 HTTP header）、前端开发成本高（要对接多个后端）。三个应对方案：

1. **BFF（Backend For Frontend）**：在前端和后端微服务之间加一层聚合服务，负责接口聚合、多端适配、接口兼容。落地选型看团队——前端用 Node.js 开发（灵活但和后端技术栈割裂）适合轻量场景，后端开发（复用基础设施但沟通成本高）适合复杂高并发场景。别在 API 网关做聚合（网关要求稳定不该频繁改）。
2. **GraphQL**：API 查询语言规范，客户端一次请求指定要的所有数据。和 BFF 是黄金搭档（BFF 是架构、GraphQL 是规范，通常在 BFF 里实现 GraphQL）。
3. **接口循环调用**：某个接口间接调用自身形成无限循环，资源消耗指数级增长或死锁。目前没有根治方案，两个预防（梳理调用链、请求唯一标识）都效果不佳，基本是事后处理。
