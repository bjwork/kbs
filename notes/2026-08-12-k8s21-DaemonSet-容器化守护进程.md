DaemonSet 保证每个节点跑一个、且只跑一个 Pod 实例，新节点加入自动创建、旧节点删除自动回收。实现上靠控制器遍历 Node 列表，给 Pod 自动加 nodeAffinity（绑节点名）和 Toleration（容忍 unschedulable 污点）。典型场景是网络/存储插件 Agent、日志收集（fluentd）、监控组件。版本管理不用 ReplicaSet，而用 ControllerRevision 这个通用对象保存完整 API 对象快照。

**我的判断**：DaemonSet 是节点级守护进程的容器化，日志/监控 agent 的标配。传统运维里 fluentd、Prometheus node-exporter、Filebeat 这些都要 ansible 批量推到每台机器装，节点扩容要记得装 agent，下线要清理，全靠流程兜底。DaemonSet 把这件事变成声明式——写一次 YAML，节点进出集群自动收敛，这才是该有的抽象。最关键的设计是 Toleration：网络插件 Agent 必须在集群网络就绪前就跑起来（鸡生蛋问题），靠容忍 network-unavailable 污点打破死循环，这个细节体现了 K8s 对基础设施分层启动的深思熟虑。我在生产里用 DaemonSet 跑过日志采集器，相比 ansible 方案省心太多。ControllerRevision 这个「通用版本对象」也值得学——不每种控制器造一套版本管理轮子，而是抽成共享 API 对象，这是好的抽象复用。
